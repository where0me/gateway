# 节点待机状态上报与紧凑卡片

## 行为

- ST 节点取得授权后，在线监测关闭的首次 10 分钟唤醒待机阶段，复用现有约 3 秒一次的参数查询节奏，在查询前发送一帧 0x8D 状态。
- 节点正在上传、发包队列非空、父节点验证未完成或未连接时跳过这次状态上报，不积压状态包。状态上报是尽力发送，不新增应用层确认重试。
- 不创建额外的心跳唤醒定时器。10 分钟结束后仍按 5 分钟 STOP2；仅在既有查询唤醒时上报一次。打开监测后仍沿用采集/上传状态上报，不为心跳改变采集周期。
- TI 原有桥接支持 7 字节 0x8D 节点载荷，追加当前上行帧的 LQI、RSSI，转发 11 字节串口载荷。TI 固件及后端无需修改。
- 后端既有处理更新 last_active、供电类型和信号测量时间；节点缓存的监测标志不覆盖数据库开关，待机状态不更新时间 last_collection。
- RSSI/LQI 是协调器接收该节点报文时的测量，不是节点测得的下行信号。STOP2 期间保留最后一次测量，不伪称实时信号。
- 当前硬件报告 Basic Power Source=4（外部直流供电），没有实现真实电池测量接口，电量显示“不适用”；未知或电池未上报显示“未上报”，不编造百分比。

## 文件

- 节点 `STM32_WPAN/App/app_zigbee.c`：待机查询前的空闲状态上报。
- 前端 `src/NodeDetails.jsx`：明确 RSSI/LQI、供电、电量展示。
- 前端 `src/App.css`：收紧卡片间距、行高、操作与状态区，长名称省略。
- 前端 `src/App.jsx`：收到有效状态遥测时恢复 Online 展示。
- 前端 `tests/node-card.mjs` / `tests/node-card-preview.*`：静态测试、独立布局预览，无真实网络或数据库写入。
- `tests/test_monitor_switch.c`：待机遥测持久化及休眠定时策略回归测试。
