# 0E 上传、网络恢复和配置同步修复

修改的是同时支持 BLE 和 Zigbee 的 `STM32WB55RGV6-BLE-Zigbee` 工程、TI `zc_cc1352R_coord` 和网关后端。未修改独立的纯 Zigbee 节点工程。

## 上传校验计时

原来接收 BATCH 批准时启动传感器校验的 10 秒期限，但执行校验还要先等有效上传许可。0E 日志中的许可确认延迟约 18.047 秒，导致第一次执行校验就超时。

现在准备批次时只初始化校验状态，取得有效许可后，在第一次执行校验时启动期限。只启动一次，许可续期不会反复延长校验期限。实际发送受阻仍保留 10 秒限制，丢包校验和重试上限继续有效。

## 网络恢复

- 一个正常恢复轮次最多尝试 3 次；完整失败或回调缺失导致本轮超时后，统一退避 60 秒。
- 上传恢复看门狗、其他恢复入口及已排队的入网任务都不能提前打断退避。若收到有效确认、通信已恢复，可提前结束退避并重新申请最旧未上传批次的许可。
- 连续两轮失败后，在退避结束、无采集/BLE 独占/待确认发送/启动或恢复事务的条件下，尝试受控的 APS/NWK 重置。同一故障期间两次重置至少相隔 180 秒。
- 重置前必须成功导出并保存**当前**网络状态和安全计数。保存失败时继续退避，不拿旧的 NVM 快照强行回滚。随后恢复刚保存的状态，并重新验证协调器；恢复 API 返回成功本身不会放行上传。
- 此路径保留网络凭据、RAM 中采集策略、BLE 应用和外部 Flash 未上传记录；不调用外部 Flash 清空或网络凭据擦除。真正的 Leave/删除优先于恢复，晚到的恢复回调不能撤销删除。
- CPU2 启动/恢复操作尚未回调时，不重复复位正在进行的协议栈操作。这次没有增加整机自动重启。

节点版本标记：`ble-zigbee-recovery-config-20261027`。

预期诊断包括：

```text
upload recovery round=... exhausted; backoff 60 s, NVM/Flash retained
runtime APS/NWK reset; restoring current saved network, BLE/policy/Flash retained
runtime network restored; coordinator verification required
upload link recovered; reapplying for oldest Flash batch
```

运行中的恢复保留缓存。重新烧录固件仍遵循此前配置的首次下载逻辑丢弃规则，两者不同。

## 普通配置与监测开关

普通独立采样参数保存到数据库后，只把最新值暂存给协调器，不立即启动无线重试。节点在上传结束、排队进入接收窗口及排队唤醒时上报配置指纹；后端发现与保存配置不一致，才在接收窗口内同步。

协调器对普通配置的重试窗口为 8 秒。窗口结束后不再提交新的普通配置发送，已提交的帧等待真实协议栈回调；下一次节点状态窗口可重新发起同步。更新配置会替换旧意图，旧 AF 回调不能重新启动旧配置的重试。参数更新不打断已采集批次。

在线监测 ON/OFF 仍保留主动可靠投递、失败后随机 3～5 秒重试的原行为。若开关尚未完成投递，随后编辑普通参数会更新其完整负载，同时保留该开关的主动投递优先级。有效应用确认会停止重试。

排队唤醒时，节点先完成一次配置同步窗口，再重新发送 BATCH 申请；不会因为唤醒而重新采集，也不会把这段等待计入新的 BATCH 发送超时。

UART 新增 `0x16`：短地址 2 字节、原配置 29 字节、投递模式 1 字节。模式 0=仅缓存，1=接收窗口，2=主动可靠投递。模式不进入 Zigbee 配置帧，也不进入配置指纹。原 `0x0C` 长度 31 的主动投递保持兼容。

## 升级

交付目录：`out/recovery-config-20261027/`。

1. 先更新 TI 协调器固件。新后端的普通配置同步需要协调器支持 UART `0x16`。
2. 更新双协议节点固件；Debug 和 Release 均已提供，STM32CubeIDE 调试使用 Debug ELF。重新烧录后可检查上面的版本标记。
3. 停止虚拟机旧后端，重新编译共享目录源码并启动：

```sh
cd /mnt/hgfs/Zigbee-Gateway/gateway-core
make -B CC=gcc
ZIGBEE_CONFIG_DIAG=1 ZIGBEE_RADIO_DIAG=1 ./gateway-server 2>&1 | tee "../out/recovery-config-$(date +%Y%m%d-%H%M%S).log"
```

附带后端二进制仅适用于 x86_64 Linux 虚拟机，RK3506 需要交叉编译。前端开发服务刷新即可更新保存提示；打包网页使用本目录的 `web/`。

建议现场复测：四节点持续上传；在 0E 排队休眠时修改周期；下一次窗口内确认新配置生效；再观察无线失败后的 60 秒退避、必要时受控恢复及积压批次重传。保留节点和后端两侧日志。
