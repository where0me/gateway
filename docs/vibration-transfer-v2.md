# 振动分块无损压缩与窗口补传（V2）

## 1. 本次实现范围

- 终端仍采集完整的一秒三轴 int16 原始值，写入外部 QSPI NOR Flash。
- 每 512 个三轴点作为独立压缩块；最后一块可以不足 512 点。
- 每轴差分、ZigZag 映射、自适应 Rice 编码。编码结果不比原始块小时，回退 RAW，精度不变。
- 一个压缩块就是一个传输窗口。窗口内按节拍连续发送；网关返回缺包位图，只补缺失分片。
- 协调器只透传 V2 帧，不替网关确认“完整收到”。
- 网关解压、校验每块和整批 CRC32，SQLite 写入成功后才返回整批完成确认。
- 前端保留三轴特征、波形、下载功能；进度改为“已校验窗口数/总窗口数”，最终显示“上传完成”，不宣称保存到了远程服务器。
- 旧版 0x8B/0x8C 接收解析保留，新终端改用 0x92～0x95，避免混解。

这次没有改串口波特率、切换 SPI、改振动特征算法，也没有改动监测策略断电恢复逻辑。已有主频计算仍是过零统计，不是本次新增 FFT。

## 3. 帧格式

全部多字节整数为小端；以下为 Zigbee 应用载荷，不含 3 字节 ZCL 头。
仍使用 0x0402 温度集群承载私有命令：终端 endpoint 1，协调器 endpoint 8，profile 0x0104。
协调器向网关转发时，在应用载荷前加短地址 2 字节；UART 保持 FE/CMD/LEN/PAYLOAD/BCC。

| 命令 | 方向 | 应用载荷 |
| --- | --- | --- |
| 0x92 | 终端→网关 | 版本1 + 批次4 + 采样率2 + 总点数4 + 块点数2 + 整批CRC4 + 三轴特征60，共77字节 |
| 0x93 | 终端→网关 | 版本1 + 批次4 + 块序号2 + 本块点数2 + 编码1 + 编码长度2 + 原始块CRC4，共16字节 |
| 0x94 | 终端→网关 | 批次4 + 块序号2 + 分片序号1 + 数据最多72，共最多79字节 |
| 0x95 | 终端→网关 | 版本1 + 确认阶段1 + 批次4 + 块序号2，共8字节 |
| 0x0D | 网关→终端 | 版本1 + 确认阶段1 + 批次4 + 块序号2 + 状态1 + 缺包位图8，共17字节 |

版本为 2。块、分片序号均从 0 开始。最后的整批确认请求，其块序号字段为总块数。
0x0D 的 UART 载荷还带目的短地址2字节，因此 UART LEN=19。

确认阶段：1=批次描述，2=块描述，3=窗口检查，4=整批完成。
状态：0=成功，1=缺分片，2=需要重发批次描述，3=拒绝/标识冲突，4=数据库或资源暂不可用，5=需要块描述，6=该块已校验。
位图 bit 0 对应分片0；置1表示缺失。接收端拒绝越界的分片序号及不匹配的长度。

79字节的业务载荷基于当前直连、网络层加密、普通3字节ZCL头、无额外源路由开销的配置：
79+3=82字节 APS ASDU。这里不是说所有 Zigbee 拓扑都固定有79字节；以后增加源路由、APS链路加密或厂商头，需要重新核对预算并升级协议。

以前说的“12个点/包”适用于未压缩数据。V2 的分片承载压缩字节流，不要求分片边界与采样点对齐；完整窗口解压后才还原 XYZ 点。RAW 回退时，72字节相当于12个三轴点。

## 4. 编码与一致性

RAW=0：按 X0/Y0/Z0/X1/Y1/Z1…排列的 int16 小端原始字节。

RICE=1：

1. 前3字节为 X/Y/Z 各自的 Rice 参数 k（0～16）。
2. 接着6字节为第一个 XYZ 原始点。
3. 后续按 X 轴全部差分、Y 轴全部差分、Z 轴全部差分的顺序编码。
4. 差分在 int32 中计算，避免 int16 极值相减溢出；ZigZag 转为非负数。
5. 位流高位在先，一元部分为 q 个0和一个1，再写 k 位余数；尾部用0补齐字节。

每块比较所有 k 的位数成本，选本轴最小者。独立块不依赖前一块字典，所以一块丢失不会阻止其他已收到块校验。
CRC32 为 IEEE 反射多项式 0xEDB88320，初值和末尾异或均为 0xFFFFFFFF；覆盖解压后的原始小端字节，而不是压缩流。

单块最多3072字节，最多43个分片。固定26667 Hz下，0.5/1/1.5秒约为13334/26667/40001点，即27/53/79块。终端只保留一个原始块缓冲和一个编码块缓冲，共6144字节，不恢复整批最多240006字节的RAM数组。

## 5. 发送与故障恢复

正常流程：批次描述确认 → 块描述确认 → 连续发送分片 → 窗口检查/缺包补传 → 下一块 → 整批CRC及入库确认。

- 初始发送节拍12ms；同时最多3个APS发送缓冲。无线栈暂时忙时延后提交，不无限塞队列。
- 新振动传输直接使用 APS 接口，保留 APS ACK 和网络安全，但不创建逐包 ZCL 默认响应事务。
- 窗口内不逐包等网关 ACK。窗口结束后等网关位图；发送节拍及APS背压仍必须保留，不能无上限发送。
- 确认等待3秒，阶段/窗口最多5次重试；本地持续无法提交10秒则暂停。
- 暂停后保留 Flash 批次，60秒后自动重试；不会因发送失败自动擦除原始数据。
- 窗口 CRC/解码失败要求补传整个窗口；正常丢包只补缺片。
- 重复块、重复确认、迟到确认均按批次与块序号匹配；不会据此提前释放其他批次。
- 网关重启丢失内存组包时，要求重发描述并重组；已在数据库完整保存的批次，会核对点数、采样率、特征和原始CRC，幂等确认而不重复入库。
- 网关最多保留16个活动组包槽，超过5分钟未活动的内存槽可回收；终端可重新描述/重传。数据库中已完成数据不因此清理。
- 数据库提交失败不返回完成确认。只有“收到APS确认”或“终端已排队”均不等于网关入库。

## 6. Flash 多批次保护

每槽60个4KiB扇区，即245760字节：首4KiB用于元数据，其余容纳1.5秒最多240006字节原始数据。
槽数按实际容量计算，最多使用16槽。例：1MiB为4槽；容量足够时为16槽。

- 保存批次、采样参数、原始CRC、三轴特征、内部顺序号和头CRC；最后写提交标记。
- 只有完整提交的槽才参与恢复上传。提交成功但头CRC异常的槽隔离，避免误擦可恢复数据。
- 收到网关整批完成ACK后，才把槽标为可复用；确认标记是NOR允许的1→0写入。
- 正在采集、未确认、隔离的槽都不作为下一次采集的擦除目标。
- 上传旧批次时可以在空闲槽采集新批次；采集优先，上传暂让出QSPI访问，随后从窗口继续。待传批次按保存顺序上传。
- 自动周期从新一轮开始计时，上传耗时不再阻止计时。若速度长期跟不上测试用1分钟周期，积压达到容量上限后会明确报错并跳过新采集，不覆盖未完成数据。
- 断电后扫描恢复待传槽。旧版单槽记录若原始CRC有效且新头区域未写过，会无损补写V2元数据；无法验证的旧记录隔离保留。
- 明确收到“彻底移除/rejoin=0”时停止上传并作废待传槽，仍须RESET才允许重新入网，避免重新添加后上传已删除设备的旧积压。

Flash保存的是振动原始值与特征，不是所有温度/麦克风历史。掉电前尚未到网关的非振动遥测不会凭空恢复；前端同批查询缺失项仍显示缺失，不借用另一批值。
本次未新增终端UTC采样时间戳；数据库现有timestamp仍沿用网关写入时间语义，不应解释为高精度硬件采样时刻。

实机建议按顺序验收：

1. 手动一次采集，看到V2批次描述、窗口进度，最终网关入库和终端完成日志；页面显示上传完成。
2. 核对数据库BLOB长度=总点数×6，特征与波形批次一致，波形/下载可用。
3. 上传中停止网关进程后重启，观察重新描述及补传，不先清库或踢节点。
4. 上传中终端RESET，确认待传Flash恢复，不混批。
5. 使用1分钟周期制造积压，确认新采集不覆盖旧批次；满槽时出现明确错误。
6. 移除设备后确认停止上传、不自行重新入网；RESET后再入网不得带回已作废积压。
