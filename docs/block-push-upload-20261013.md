# 分块主动回复与高速串口（2026-10-13）

## 已实施

- TI 协调器与后端串口均改为 921600、8N1，不启用硬件流控；节点调试串口没有改速率。
- 后端串口驱动校验设置结果，失败时关闭串口并报错，不再错误打印初始化成功。
- TI 使用 32 字节 partial 接收：短命令在接收空闲时也会回调，不必等满缓冲区；UART 命令优先在应用任务处理，不在中断调用 Zigbee API。
- 第一块仍申请初始许可。后续块的压缩长度、编码方式、CRC 元数据保留，但块成功回复就是下一块许可，不再重复申请。
- 普通分片不产生应用层 ACK。整块收齐后自动解压、校验并回复；收到末片但仍缺片时等待至少 200 ms 空闲再请求补传。未收到末片时以至少 1500 ms 接收空闲触发缺片检查。
- 修复请求发出后不在没有新分片时反复发送。回复丢失、全块数据丢失或元数据丢失，节点仍可在 3 秒超时后查询恢复，最多重试 5 次。
- 按批次和块过滤迟到/重复成功回复，补传中的重复相同位图不增加失败计数。
- 整批 CRC 校验、数据库提交、特征确认与 Flash 释放顺序不变。
- TI 0x37 逐条回复诊断已按要求移除；后端也静默忽略旧固件发送的此类诊断。原有下行失败提示保留。

## 未实施的部分与限制

“后端判醒会话 + ST 临时常收 + TI 绕过休眠子节点缓存直发”未实施：
现有 SDK 的公开接口中没有找到可验证支持整套切换的方法。
没有强改父节点记录的 RXONIDLE 能力位，也没有把 skipRouting 当成绕过缓存选项。
当前节点仍以休眠终端身份入网，保留已有的协议栈快速轮询。
本次不承诺消除 0xF0，不代表实现了不依赖 MAC 轮询的直发。
BLE、QSPI/DMA、采样周期、分组、在线监测开关以及 TI +5 dBm 均未改变。

## 更新与验证

停止后端，烧录新的节点与协调器固件，在网关 Linux 上重新编译并启动后端。
新版接收器与旧版逐块等待许可的节点不兼容，不能只更新其中一端。
协调器与后端必须同时切换至 921600；其他串口软件若连接这条链路也需改为同速率。
不要全片擦除，正常更新固件即可；本次不要求重新入网。
Windows 生成的 x86_64 Linux 后端仅用于编译验证，不能直接替换 ARM 网关上的可执行文件。

自动测试覆盖压缩/CRC、丢失中间片/末片/块确认/块元数据、迟到与重复回复、
数据库失败及恢复、Flash 保留与恢复。BLE 与 DMA 源码保护检查通过。
实际射频速率、0xF0、STOP2 和 USB 串口在 921600 下的稳定性仍需要硬件测试。
