# 采集完成后的排队显示（2026-10-28）

节点发送BATCH申请时已经完成采集。网关回复WAIT并打印“上传排队/排队复查”后，节点卡片必须显示“等待数据上传”，而不是继续显示采集中。

此前排队分支只回复了节点并打印终端日志，没有更新设备状态或推送排队事件。现在：

- 排队时按MAC和批次保存 `collection_state=waiting`，保留历史测量记录及采集批次标识。
- 立即推送 `vibration_upload_progress`，包含 `status=queued`、批次、窗口总数和等待时间。重复排队查询沿用10秒内合并日志/状态通知的策略。
- 后端重启的35秒保护窗口也表示采集已经结束，同样推送等待上传状态。
- 前端收到事件即切换“等待数据上传”；未到本批上传阶段时保持测量区为空、波形按钮禁用。
- 同批次迟到的CAPTURING事件或旧HTTP快照不能把排队状态退回采集中；新的不同批次仍可正常开始采集。
- 同批次已经完成后，迟到的排队事件不再覆盖完成结果。

无需修改或烧录节点、协调器。本次更新后端和前端：

```sh
cd /mnt/hgfs/Zigbee-Gateway/gateway-core
make CC=gcc
ZIGBEE_CONFIG_DIAG=1 ./gateway-server
```
