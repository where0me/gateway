# 延迟离网与节点逻辑恢复出厂（2026-10-03）

## 修改范围

后端：`gateway-core/src/main.c`、`src/db_manager.c`、`include/monitor_protocol.h`。
节点（纯 Zigbee 工程）：`app_zigbee.c`、`sensor_app.c/.h`、`zigbee_vibration_store.c/.h`。
协调器：`gateway_bridge.c`。前端未修改。

## 行为

- 点击删除仅事务性建立 revoked_nodes 任务、删除业务数据和节点独立采样策略，不立即发 Leave。
- 新公告仍用 UART 0x84 更新 MAC/短地址；恢复 hello 新增 UART 0xA0（IEEE 8字节、短地址2字节，小端），只作为活动，不插入待授权节点。
- 采样配置查询、名称响应、信号探测、传感器和所有波形阶段均先检查踢出任务；首个新通信立即触发离网，重复分片沿用3秒节流。
- 0x8F 完成扩展为14字节：IEEE[8]、short[2]、TC清理状态、APP清理状态、持久化状态、完成标志。只有标志=1且三个状态=0才清除任务；旧10/13字节事件不会清除任务。
- 协调器只对匹配离网任务、非重入的 Leave indication 进入清理。清理失败保留槽位，并每3秒重试；TC/APP共用表的“已无绑定”需读取核实后才规范化为成功。
- 不把本地 NLME confirm 或 APS confirm 当作节点完成本地清理的证明；完成标志仅表示协调器侧离网事件及安全记录清理持久化完成。
- 节点在恢复后尚未确认应用通信时也接受真实 Leave；失败 fresh join 的本地回滚事件仍保留原入网期限。
- 节点在任务上下文停止麦克风/振动，写内部 EEPROM 清理中标记，然后将全部波形槽 magic 写0并读回核实。原始数据字节保留，不格式化、不整片擦除，下一次采集由 Begin 擦除目标区域再写入。
- 全部槽失效并重新初始化后格式化节点 EEPROM 网络区，重置协议栈、授权、业务内存及默认采样参数（300秒/500ms振动/1000ms两种麦克风）。清理完成才开启30秒新节点入网窗口，未入网沿用5分钟STOP2重试。
- 若 Flash 清理失败：阻止入网，保存标记，下次重启继续清理。清理中标记首次写入前断电仍存在很短的未持久化窗口；不能声称任何时刻断电均已清除。
- 删除不是永久黑名单，清理后再次开放网络可作为未授权节点出现。

## 验证及硬件验收

新增 `tests/test_node_store_reset.c` 模拟 NOR 1->0写入：验证失败阻止写入、重试、重启记录失效、原始字节保留、下一次采集重新擦除并写入。
数据库测试使用内存数据库。固件需同时更新节点和协调器，后端重新编译启动；未执行硬件烧录或真实数据库删除。

最终结果：节点与协调器 Debug/Release 均编译成功；协调器有原有 `Init_Debug` 未使用警告。后端 main/db_manager 已生成 Linux musl 目标对象文件。独立 NOR 清理、数据库、V2 波形协议测试通过。原总测试脚本被旧 BLE 工程 vibration_wire.h 副本不一致拦截，因此不能宣称整个总测试套件通过。

验收：节点休眠后点击删除，确认没有即时串口 Leave；下一次节点活动触发请求，完成后任务消失。节点应输出 Flash records invalidated 和 network data erased，出现30秒新入网扫描；关闭允许入网验证5分钟STOP2；再允许入网授权，验证新批次正常采集上传，旧批次不恢复。
