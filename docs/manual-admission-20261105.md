# 手动确认入网与自动监测（2026-11-05）

## 使用流程

1. 用户点击“允许节点入网”，协调器持续开放网络，直到点击“禁止节点入网”。界面不再倒计时。TI 接口仍使用 254 秒窗口，在协议栈确认后提前 30 秒自动续期；提交失败时每 5 秒重试。协调器重新上电默认关闭开放网络。
2. 节点完成无线入网后，协调器继续发现端点、Cluster、采集协议和型号。失败的识别会重试，型号未读到时也持续重试；后端每 5 秒轮询一个缺少型号的候选节点补读。
3. 首次展示只要求三类条件：入网通信已确认；识别信息齐全（ready 状态、有效名称/型号、实际上行测得的 LQI/RSSI）；当前允许加入且尚未获用户授权。不以独立探测成功作为首次展示或首次确认入网的前提。列表仅展示设备名称、型号、MAC、LQI、RSSI，以及“确认入网”按钮。
   后端首次将节点返回待授权列表后，才为它安排主动探测，首次随机等待 3～10 秒。尚未展示过的候选只继续识别，不发独立信号探测。后续自动探测在上一次回复或超时后随机等待 3～10 秒；各节点独立随机，网关相邻探测至少错开 150 ms。标题右侧“刷新”按钮对已经展示过的候选立即启动一轮探测，包括后续隐藏的候选；多个节点依次发送，已有未结束的请求不重复叠加。页面每 2 秒读取最新结果，节点回复后更新 LQI/RSSI。
   每次等待回复 3 秒，连续 3 次无有效回复则从待授权列表隐藏，并拒绝旧页面的确认入网请求。后台数据库记录保留、不下发离网；自动探测继续进行，收到匹配的新回复且识别齐全后重新显示。普通列表读取或普通状态上报不重置这项隐藏判定。关闭允许加入时，隐藏候选与可见候选一起清退。后端重启后按上述三类条件重新首次展示，再开始新一轮探测。
   探测回复携带协调器收到该帧时测得的 RSSI 和 LQI，必须匹配当前短地址、请求编号和有效期。迟到、重复、错误编号与旧地址回复不恢复可见性。串口本地写入失败不计入节点无应答次数。原有节点状态上报仍承担配置与网络维护，不替代这项探测判定，也不会生成待授权节点的首页业务活动。
4. 待授权节点不进入 STOP2，保持快速 MAC 取包轮询，每隔随机 3～10 秒上报一次链路状态。节点没有获准采集和批次上传。待授权列表仅在允许加入时展示，点击禁止加入即隐藏列表，并将所有未授权节点（包含未识别完整的候选）保存为清退任务、下发离网命令。关闭后迟到的宣告也会清退；未完成的清退任务跨后端重启保存，并在节点上行时重试。已授权节点不受影响。
5. 用户确认后，数据库在同一条更新中保存授权并开启监测；随后发送启用配置。节点收到后立即开始第一轮采集。没有单独的在线监测开关，旧开关接口返回冲突提示。配置未投递时保留授权意图，下一次节点状态接收窗口继续同步。
6. 已授权节点的后续采集、错时排队、补传、休眠、重连采集时间恢复维持原规则。重复点击确认不会重复下发启用配置。首页最新活动和正式列表均只展示已授权节点。

这里的“用户确认入网”属于网关应用授权。为了识别型号、读取信号，节点在此之前已经是无线网络成员。待授权的“活跃”指 CPU1 不进入 STOP2，协议栈持续维护连接与快速取包；无线芯片仍由 Zigbee 协议栈调度收发，并非永久占据信道。

## 数据与兼容

- `join_confirmed`：入网后有效通信证明。
- `user_authorized`：持久化的用户授权，独立于前者。
- 新节点默认未授权；仅有设备宣告、名称或短地址不能获得授权。
- 节点收到网关明确的关闭监测策略时按待授权处理，即使节点旧 NVM 中曾经保存了授权，也不能据此进入待机休眠。这覆盖网关数据库被重新初始化后的重新确认场景。
- 首次升级时，已有正式节点保留授权，并统一启用监测。后续后端重启不会自动授权新候选节点。
- `/api/device/pending` 仅在允许加入时返回识别齐全的未授权候选；`POST /api/device/authorize` 校验开放状态并原子校验识别条件后授权。禁止加入后旧页面发来的授权请求被拒绝，重复授权不重启采集。
- 待授权节点的状态只更新内部识别与信号数据，不生成首页采集活动；未授权标量、波形、清单报文不会进入采集入库/上传排队。

## 部署

本次需要一起更新：前端、网关后端、TI 协调器和 BLE+Zigbee 节点固件。旧节点固件不具备新的待授权常醒规则。

主动探测补充修改仅需重新部署前端、后端及重新烧录协调器。已使用上述手动授权版本的节点无需再次烧录，节点原有编号回显应答保持兼容。协调器串口探测回复由 5 字节扩为 6 字节，保留原 RSSI 偏移并追加 LQI；旧协调器回复不能证明本次 LQI，会按未获得有效探测回复处理，必须配套更新协调器。

“先展示、后探测”修订仅修改后端；更新后端并重启即可，前端和节点、协调器沿用已部署版本。旧协调器虽不妨碍首次展示，但不能刷新新的双指标探测结果，仍需使用已更新的协调器版本。修订产物与修改前备份位于 `out/admission-first-display-20261105/`。

虚拟机运行后端：

```sh
cd /mnt/hgfs/Zigbee-Gateway/gateway-core
make CC=gcc
ZIGBEE_CONFIG_DIAG=1 ./gateway-server
```

节点启动版本标记：`ble-zigbee-manual-admission-20261105`。已有按下载标记丢弃外部 Flash 缓存的规则继续生效；请在烧录新固件后采集新的测试数据。

源文件修改前备份：`out/manual-admission-before-20261105/`，其中 `0` 是网关工程、`1` 是节点工程、`2` 是协调器工程。数据库升级会添加授权字段，部署前应在停止后端后备份正在使用的数据库文件及伴随 WAL 文件，避免复制不一致的运行中 SQLite 文件。

主动探测修改前另存源文件：`out/admission-probe-before-20261105/`。

## 验证

- 实际 SQLite/API 测试：识别缺项隐藏、补读、五字段输出、明确授权、自动启用、重复授权、关闭清退所有候选、已授权保护、迟到宣告、离线及重启后保留清退任务、后续重新入网和老数据库迁移。
- 主动探测测试：手动触发真实下行、匹配编号、三次无回复隐藏且不撤销、隐藏后自动随机重试恢复、地址改变使旧结果失效、本地串口失败不计数、保留电源属性；提取真实协调器接收函数验证回显编号和本帧 LQI/RSSI。
- 首次展示测试：首次返回列表和确认入网均不要求独立探测回复；未展示前不探测，首次返回后随机安排探测；连续失败隐藏后普通 GET 不重置隐藏状态。
- 提取真实节点函数测试：未授权保持 STOP2 禁止、随机状态间隔、OFF 不授权、首次授权立即采集、旧节点恢复时保留采集计划。
- 提取真实协调器函数测试：实际状态展示、开放重试、自动续期、手动关闭取消续期、计时器回绕。
- 前端构建和组件测试：待授权区域、去掉开关与倒计时、首页过滤未授权活动。
- 端点/Cluster 识别、入网可见性、可靠控制、上传恢复、重连采集计划与四次通信失败分类回归测试。
