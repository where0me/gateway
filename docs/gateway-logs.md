# 网关日志第一版

修改范围：前端、后端；节点和协调器固件不变。

## 运行与保存

在 gateway-core 目录执行 `make` 后重启后端。日志保存在独立的
`data/gateway-logs.db`（SQLite WAL），不依赖节点业务表，也不会随节点删除被级联删除。
从新版后端启动开始记录，不导入以前的控制台文本。

串口线程只向 512 项内存队列追加事件。主线程每 500ms 批量保存，单批最多 32 项，
写入失败会保留队列重试；队列满时保留原有事件、丢弃新事件，并在 API 返回丢弃计数。
每分钟清理超过 7 天的日志及超过最新 50,000 项的记录。
Ctrl+C / SIGTERM 正常退出会刷新缓冲；突然断电/强制结束可能丢失尚未保存的缓冲记录。

## 查询接口

`GET /api/logs`

可选筛选：`level`（INFO/WARN/ERROR/DEBUG）、`source`（backend/coordinator/node/frontend）、
`mac`、`q`（说明、事件标识、MAC 的字面子串）、`from` / `to`（Unix 秒，含边界）。
接口仅查询后端本次启动后的记录，按日志 ID 倒序返回，limit 支持 100、200、500、1000，默认 100，不提供页面分页。
启动时记录已有最大日志 ID，查询只接受更大的 ID，不依赖系统时间划分运行批次。
旧记录仍按原有 7 天 / 50,000 条策略保存，但不会出现在本次运行的日志页面中。
响应包含 status、items、total、page、limit、dropped、retention_days、capacity。
时间为后端事件时间；短地址和批次未知时为 null。所有用户筛选使用参数绑定。

## 页面

侧边栏“日志”：黑底等宽字体窗口，按等级着色，带行号和横向滚动。
主页面保留等级、来源、节点三个即时筛选；右侧依次为日志上限、清空、刷新。
上限可选 100、200、500、1000，默认 100，主窗口每 2 秒读取本次运行的最新匹配日志。
清空在当前浏览器标签页保存已显示日志的 ID 边界，自动更新、刷新、切换页面后返回以及
刷新网页均不会重新显示边界之前的记录；后续新日志仍显示，数据库不受影响，查询和导出
仍可读取这些日志。不同网关分别保存边界；关闭标签页后，新会话可重新查看。
右上角“查询日志”先打开条件窗口，可选择等级、来源、节点、开始及结束时间；
确认后关闭条件窗口并打开结果窗口，显示最新 100 条匹配结果（快照、不自动刷新），不改变主窗口筛选。
没有关键字输入框、实时更新开关及分页按钮。
“导出日志”打开配置弹窗，按等级、来源、节点及开始/结束时间查询后生成 CSV，
最多导出本次运行的最新 100 条匹配日志，超过上限明确提示，无匹配记录不生成文件。
后端连接失败时清空旧显示，重连成功后显示新结果。日志只读，不提供删除入口。

## 事件边界

记录启动/正常停止、串口打开和读取错误、协调器网络状态变化、发现和授权节点、
节点宣告及恢复活动、在线超时、离网、采样配置保存/提交/提交失败、采集上传状态、
特征及完整波形保存、清退任务创建/重试/完成，以及名称和描述修改。
日志使用 MAC 稳定关联；界面名称使用当前授权列表，没有授权记录时直接显示 MAC。

不记录网络密钥、原始波形包及每个包的进度。不把入网宣告或恢复活动等同于
应用握手确认，也不把“配置提交协调器”写成“节点已应用”。现有报文不提供具体
失败原因或应用确认时，日志明确标注信息边界。没有额外上传固件串口调试文本。

## 验证

`tests/test_gateway_logs.c`：隔离数据库，验证筛选、分页、参数安全、重启保留、
真实并发生产队列、写失败重试、队列溢出、7 天清理与 50,000 项容量限制。
`gateway-ui/tests/gateway-logs.mjs`：页面结构和 CSV 转义/公式注入防护。
Linux 完整编译通过不等于虚拟机和设备端实机验证，部署后应实际检查一轮采集和清退日志。
