# 节点页面的批次采集时间

节点卡片与传感器趋势图使用同一个批次的 `captured_at`，不再把数据上传到达时间显示为采集时间。

当前节点协议没有提供带日期的绝对采集时间。因此此字段的含义是：**网关首次收到该节点、该批次“开始采集”通知的时间**。它近似反映采集开始时刻，包含通知传输的延迟；不是节点 RTC 的精确采样时间。通知丢失或采集时网关未运行的批次，保持未知。

- `collection_capture_times` 按 MAC、批次号记录，重复通知不覆盖。
- 进入排队、补传、入库、上传完成均不会改写采集时间。
- 数据库记录在后端重启后保留；删除节点或清除节点历史时一并清除。
- 节点列表接口、监测状态 WebSocket、指定振动批次接口及采集历史接口提供采集时间。
- 趋势图优先按采集时间排列；旧记录缺少该字段时保留原有顺序依据，但时间显示为“采集时间未记录”，不使用上报时间冒充。
- 采集下一批与上传上一批重叠时，前端分别保存两批时间，随显示批次切换。
- 现有 `timestamp` 字段继续表示网关接收/入库时间，供其他功能使用。

验证：采集时间数据库回归（重复通知、排队、完成、历史顺序、节点隔离、旧记录及重启），实际振动批次与节点列表 API，前端批次状态合并、卡片和趋势图渲染；完整 Linux 后端编译及前端生产构建。

在虚拟机停止旧后端后，在 `gateway-core` 执行 `make CC=gcc` 并重新运行后端；前端开发服务刷新页面即可。数据库表自动创建，不需要烧录节点或协调器。后端升级之前的批次没有采集时间记录，后续收到采集开始通知的新批次才有该时间。
