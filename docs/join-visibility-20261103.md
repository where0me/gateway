# 入网确认后显示节点（2026-11-03）

设备宣告只建立内部 MAC/短地址映射，供协调器继续读取描述符和完成应用通信；前端不再立即显示节点。

## 显示依据

收到以下任一有效确认，保存 `devices.join_confirmed=1`：

- 节点主动发送的有效 A4 控制状态（包括未开启监测时的正常状态）。
- 节点主动发送的 99 配置查询，原因为入网/恢复、上传后或待机。
- 节点主动发送的有效 8D 监测状态。
- 协调器 A2 `ready`，该状态由其收到 HELLO 后节点的主动状态/配置查询产生。

确认必须匹配当前登记的 MAC 和短地址。单独的设备宣告、型号、描述符、协议属性、邻居表 LQI，以及发送提交成功均不作为确认依据。本工程节点的这些主动报文在其入网成功/恢复验证后发送；这不是将 Device Announce 当作完整安全入网成功。

确认后终端打印 `[节点入网确认]`，下一次前端轮询（约 3 秒）显示节点。不要求开启监测，不要求先采到传感器数据，也不依赖 RSSI/LQI 是否有效。

## 数据和界面

- 确认标记持久化；正常休眠、离线、网关重启或重新识别失败不会清除它。
- 删除节点后重新添加，必须重新获得确认。
- `/api/device/list`、采样策略的节点列表、全体采集/监测及信道迁移排除尚未确认的记录。
- 手动添加只登记 MAC，不再由前端构造一个临时节点；正式确认后自动显示。
- 内部未确认记录保留地址和识别信息，不增加待授权界面，不向节点额外发送删除或离网命令。

旧库首次升级采用事务新增列和迁移：有 `ready` 识别记录或历史采集数据的节点保留显示；只有宣告、名字、地址、在线状态或信号测量的记录不自动确认。原始业务数据不删除。较老固件没有上述主动状态且旧库无确认依据时，需要等后续有效上行确认。

## 使用

停止虚拟机中的旧后端，在共享工程执行：

```sh
cd /mnt/hgfs/Zigbee-Gateway/gateway-core
make CC=gcc
ZIGBEE_CONFIG_DIAG=1 ./gateway-server
```

前端开发服务使用共享源码，刷新页面即可。若部署到 RK3506，应使用 ARM 发布构建脚本重新构建，不能使用本目录的 Linux x86_64 测试二进制。
