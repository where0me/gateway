# 振动上传前的同批次数据校验

2026-10-26，适用于 `STM32WB55RGV6-BLE-Zigbee`、`zc_cc1352R_coord` 和当前网关后端。

## 行为

含振动的批次在取得上传队列许可后，先确认温度、磁场XYZ和本次采集实际启用的两个麦克风声级。接收端按 MAC + 批次号检查已经提交到 SQLite 的数据，并核对各项的 CRC32。节点声明“启用但未采到”的项记录为采集缺项；实际采到的项全部匹配后，允许节点开始振动波形或特征传输。协调器只转发清单、数据和确认，最终确认由网关后端给出。

每批清单基于传感器开始采集时锁定的 `ZigbeeSensorEnableMask`，不读取上传时的新配置。当前温度、磁场始终启用；数字和超声麦克风按该次实际开关决定。例如：旧批次采集时数字麦克风开启，即使上传前又下发了关闭配置，旧批次仍须补齐数字麦克风；采集时关闭的通道无需等待，也不补成零值。

流程：

1. 采集结束，把数值、有效位图和本批应有位图保存到对应的外部 Flash 批次元数据。
2. 原有 `0x92` 上传许可/排队流程继续执行。
3. 获准节点发送 `0xA5` 数据清单，先查询同批次接收情况。
4. 本批应有但未采到的项，由清单明确报告，后端终端打印“节点采集缺项”，并写入前端日志使用的日志数据库，级别WARN、事件 `sensor_capture_missing`，包含MAC、短地址、批次和具体传感器名称。同一次上传中重复清单不重复记录警告。
5. 网关返回实际采到但接收端缺失或校验不符的项，节点只从该批次 Flash 读取并补发相应的 `0x86`～`0x89` 报文，再次发送清单复核。已确认的采集缺项不要求补发；其余项入库且 CRC 匹配后开始振动传输。
6. 振动原始值和特征仍沿用原有完成确认及 Flash 释放规则。

收到 APS 确认、进入本地发送队列、接收了其他批次或其他节点的数据，都不能替代这次确认。0声级、负温度、负磁场都是有效数值，按非NULL与CRC判断。

## 重试与异常

每个清单确认最多发送5次，确认等待3秒；本地持续无法入队的上限为10秒。丢失确认时先重新核对清单，不重复发送已确认正确的值。失败后保留 Flash 批次并报告错误，后续按原上传队列重试。

如果传感器本来启用却根本没有采到有效值，记录警告、跳过该项，继续发送本批其余数据，不用零值或另一批数据凑齐。如果有值但传输丢失，则仍按原规则补发。整份元数据不存在、损坏或版本不支持时，不能确定本批的采集情况，节点仍保留批次并报错。

网关重启后，节点重新申请上传许可、重新核对清单；已经入库的数值可以直接确认，不要求全部重发。旧80字节快照的预留字节为0时，按原快照实际有效位图校验；旧快照没有记录当时的启用策略，因此无法追溯“本应采集却没有采到”的项。没有快照的更老批次保留但不直接放行波形。

## 存储与协议

`Custom_APP_ZigbeeSnapshot_t` 大小仍为80字节：原来的末尾两个填充字节分别用于 `scalar_required_mask` 和 `scalar_policy_version`，偏移78、79。Flash记录仍使用原来的长度和CRC封装。

新增 FC10 命令 `0xA5`，节点载荷24字节：

| 偏移 | 内容 |
| --- | --- |
| 0 | 传输版本2 |
| 1～4 | 批次号 LE32 |
| 5 | 数据清单版本1 |
| 6 | 本批应有位图 |
| 7 | 本批实际采到的有效位图 |
| 8～23 | 温度、磁场、数字声级、超声声级各自 CRC32，LE32 |

位图：bit0温度，bit1磁场XYZ整体，bit2数字麦克风，bit3超声麦克风。各项CRC覆盖对应命令标识、批次号和原有整数载荷。校验前将数据库浮点数按原始线精度还原为整数，不使用设备最新影子值。

确认沿用17字节 `0x0D`，阶段kind=6：OK=0表示实际采到的项全部匹配，且采集缺项状态已经保存；MISSING=1的位图只表示实际采到但需要补发的项；REJECT=3表示同批次清单冲突；STORE_FAILED=4表示需要重试保存；NEED_BATCH=2表示先重新申请上传许可。原有振动描述长度、窗口CRC和缺片补传协议不变。

网关也用已确认的本批清单修正尚未导出的 MQTT 批次传感器策略，避免把后来下发的新配置套用到旧批次。`mqtt_batch_state` 新增 `scalar_unavailable` 列，启动时自动兼容升级旧表，旧记录默认为0；状态保存成功后才能放行振动。MQTT只等待实际采到的值，采集缺项输出 `null`，并附加 `capture_status: {complete:false, unavailable_measurements:[字段名...]}`。`collection_complete` 仍表示整批传输已结束，`capture_status.complete=false` 明确表示采集有缺项。即使全部配套传感器都未采到，已有振动数据仍可导出。已经导出的不可变消息保留原快照。

本次校验针对含振动的批次及其配套传感器值；只采温度等、不含振动的分支继续沿用原有上报流程。
