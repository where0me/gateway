# 分组批量采样参数

分组是管理与批量设置，不提供采样时间同步或无线上传调度。组名可重复，
分组 ID 唯一，一个节点最多属于一个组。

- 新组没有已应用参数，成员继续使用各自配置。
- 分组列表和详情增加“采样参数”。打开窗口或编辑参数不保存，只有
  “应用到全组”才将参数保存到 `node_group_sampling`，并原子更新当前成员
  各自的独立采样策略。空组也可应用，作为以后成员的模板。
- 向已应用参数的组添加节点，仅新增成员继承模板；已有成员不会因保存组名、
  描述或成员列表而反复被覆盖。未应用组参数的组新增成员不改变采样设置。
- 再次应用组参数覆盖全部当前成员，并更新以后成员继承的模板。
- 从组移除、删除组，不重置已经分配给节点的参数，不删除历史数据、不离网。
- 各节点的在线监测开关不变；后端不发送串口控制命令。睡眠、正在采集上传
  的节点沿用现有流程，下次主动查询才取得保存的新参数。

参数范围复用节点设置：周期、振动/数字麦克风/超声麦克风窗口、
原始波形上传频率及传感器启用选项；采样率仍为硬件固定值。
隐藏的旧轮询/接收窗口字段保持各节点原值。

接口：GET `/api/groups` 返回 `sampling_applied` 和 `sampling_config`；
POST `/api/groups/sampling` 接收分组 `id` 以及与节点采样设置相同的参数字段。
成员列表由后端数据库决定，不信任请求提供的成员或策略 ID。
参数和所有成员更新处于一个事务，失败时整批回滚；成员继承也与成员保存原子提交。

验证：`tests/run-monitor-switch.ps1` 中的分组测试覆盖未应用、首次应用、
重复应用、新成员继承、成员独立修改不被普通编辑覆盖、空组、
故障注入后的整批回滚、重启保留、删除组不重置节点及唯一成员约束。
已有节点采样配置测试同时回归。

部署只更新前端和重新编译、重启后端，数据库自动增表；无需擦库、烧录节点或 TI。
