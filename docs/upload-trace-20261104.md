## 如何对应

共同字段为短地址、批次、窗口、分片及内容指纹。网关还会查出 MAC；节点通过其串口会话对应 MAC。窗口、分片在新增日志中都从 1 开始；节点快照中的 0、网关日志中的 `-` 表示不适用。

| 记录 | 证据范围 |
| --- | --- |
| 节点 `stage=提交尝试(11)` | 应用调用上传发送接口前的尝试，不证明已经发射或提交成功 |
| 节点 `stage=发送结果(12)` | 协议栈对该请求的最终结果；包括本地立即拒绝，`late=1` 表示旧上传代次回调 |
| 协调器应用层收到 | 包已到达协调器 AF/ZCL 应用接收入口，不等于已经通过业务筛选 |
| 协调器拒绝上行 | 子节点表没有地址、协议识别未完成、端点/集群/方向不匹配，或清单格式无效 |
| 协调器串口转发结果 | 本机 UART 写入是否完整，不证明 Linux 后端已经收到 |
| 后端串口收到 | 串口解析器已经校验并分发此消息；不代表该包通过后续数据库/上传状态检查 |
| 后端生成回复 | 后端决定了回复类型及内容，尚未证明串口提交成功 |
| 后端串口写入结果 | 本机串口驱动完整接收了回复帧，或返回短写/错误；不等于协调器接收 |
| 协调器提交回复 | 对应回复交给协议栈的提交结果；AF 事务号、ZCL 序号一并保留 |
| 协调器回复投递结果 | 该 AF 事务的最终状态，包括成功、未收到确认、间接事务过期/清理 |
| 节点 `stage=收到回复(8)` / 最近回复收到 | 节点应用接收处理入口确实拿到了该回复，不保证状态机接受了它 |

节点已有的“窗口已校验”“许可已确认”“raw/features confirmed”日志才分别证明相应业务状态已经推进。新增诊断不会把“收到旧回复”当作“应用了旧回复”。

内容指纹是消息体的 32 位 FNV-1a，便于判断内容是否相同，不是唯一事务 ID，也不是密码学证明。重发相同内容会有相同指纹，需结合节点/协调器 ZCL 序号和记录顺序判断具体尝试。后端原有转发包不带 ZCL 序号，明确显示“未提供”，不伪造逐次对应关系。监测状态只对共同的六字节前缀计算指纹，避免协调器附加电源/RSSI/LQI 后产生不同指纹。

`附加值` / `detail_low` 为回复数据的低 32 位：许可续期时为 nonce，窗口缺片回复时为缺片位图低 32 位；它不是完整 64 位位图。完整缺片位图仍见原有“振动补传”日志。

协调器、后端和节点的时间分别为各自的单调时间，不能直接相减；源记录号也只在各自记录器内递增。协调器/节点重启、短地址变更时需要按 MAC、批次及启动日志重新对应。

## 何时输出

常态只向 RAM 保存元数据，不复制原始波形、不保存密钥、不逐片打印或写入日志数据库。

- 协调器：最近 96 条，共享环形记录；一次仅回放目标短地址最近最多 48 条。
- 后端：最近 96 条，共享环形记录；一次仅回放目标短地址最近最多 48 条。包含收到的数据、生成的回复和本机串口写入结果。
- 节点：最近 24 条收发记录，另保留最近一条完整的 17 字节上传回复用于本地解码输出。它只是上传协议回复，不含密钥或传感器原始波形。
- 同一短地址的自动快照最多每 10 秒一次，避免失败风暴；普通失败日志仍按原规则输出。环形覆盖总数会明确显示。不同节点有独立的限流记录。

触发方式：

| 来源 | 原因编号 | 触发点 |
| --- | --- | --- |
| 协调器及后端 | 1 | 上传回复提交或 AF 投递失败 |
| 后端 | 2 | 收到节点“采集/上传异常”状态，并向协调器请求历史 |
| 后端 | 3 | 活动上传许可因 60 秒无上传活动而过期，并请求协调器历史 |
| 后端 | 4 | 本机回复串口写入失败 |
| 协调器 | 5 | 上行业务筛选拒绝或本机串口转发失败 |
| 协调器 | 6 | 收到后端主动请求的历史快照 |
| 节点本地 | 1 | raw/features 上传失败路径 |
| 节点本地 | 2 | 链路可疑，暂停上传并开始验证协调器之前 |

节点断链时，其异常状态本身也可能发不出去。网关无法瞬间知道节点本地发生了四次失败；若没有收到异常上报，活动上传会在原有 60 秒无活动检查时触发网关快照。这只是观察，不提前撤销许可，也不修改恢复流程。

后端终端输出详细快照，前端日志保存一条带 MAC/批次的“上传链路快照”摘要。节点详细快照输出到节点调试串口，需要同时保存两端日志。

## 判读示例

相同批次/窗口/分片和指纹：

1. 节点有提交尝试，协调器有接收记录：该包到达过协调器应用层；不能再直接归因为“协调器没有收到”。
2. 协调器收到且完整写入串口，后端缺少记录：优先检查串口链路、解析及诊断历史是否已被覆盖。
3. 后端生成并完整写入回复，协调器没有提交记录：检查下行串口、协调器接收与日志覆盖情况。
4. 协调器回复投递失败，而节点有相同回复的接收记录：需要区分重试/重复回复及返回确认丢失，不能把最终失败直接等同于节点未收到。
5. 节点收到了回复，但没有窗口推进日志：检查回复批次、窗口、nonce、状态与节点当前阶段是否匹配。

有限历史不保证完整：未看到某条记录，不等于该包没有到达。确认某次无线帧实际发射、MAC ACK 是否在空口出现，仍需空口抓包。本次不把间接事务过期等最终状态冒充为逐次发射/轮询证据。
