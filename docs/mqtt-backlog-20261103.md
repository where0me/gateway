# MQTT待上传总量统计

## 页面调整

- “待上传批次”改为“待上传批次总数”。
- 删除“待上传统计为当前目标已入队的批次；关闭期间的本地采集记录会在重新启用后继续整理和补发。”提示。
- “待上传数据量”统计完整待发送内容的合计，包含原始波形及传感器/特征快照。

## 统计口径

状态接口 `/api/mqtt/status` 和设置接口里的 `runtime.pending_batches`、`runtime.pending_bytes` 使用同一口径：针对当前保存的服务器/账号/分组/网关标识，统计所有已完整入库且尚未发送完成的本地批次，不再局限于已进入 `mqtt_outbox` 的条目。

包括关闭上传、节点离线、队列容量限制、等待整理的完整批次。已经发送完成的历史批次不计入；同一MAC和批次的多份待发修订只计一个批次，但数据量包含各份仍待发送的内容。传感器数据或振动尚未完整到达网关的记录不作为完整MQTT待发批次。

待发快照已发送而原始波形尚未发送时，数据量只保留未发送的原始波形。未整理与已整理使用相同的测量快照字节数加原始波形字节数，整理入队不会凭空改变数据量。大小不包含动态消息标识、Protobuf和MQTT/TCP封装，因此不是空口或网线流量计数。

服务器/账号等目标发生变化时，当前目标需要的数据重新按该目标计算；其他旧目标的已有待发队列保持原有隔离提示和处理规则，不跨服务器擅自转发。

## 实现

新增 `mqtt_store_backlog_stats`，对未入队源记录复用与正式发送完全相同的完整性检查和快照比较，避免历史已发送数据在重启或被重新标记dirty后被重复计算。统计使用只读事务，不创建发送任务、不清除dirty、不修改确认标记、不打开MQTT连接；不受发送队列容量限制。增加振动表MAC/批次索引，供源记录定位使用。

保留原来的 `mqtt_store_stats` 和 `mqtt_store_pending` 供发送队列内部使用，发送调度和Sparkplug报文没有改变。

## 使用

虚拟机停止旧后端后：

```sh
cd /mnt/hgfs/Zigbee-Gateway/gateway-core
make CC=gcc
ZIGBEE_CONFIG_DIAG=1 ./gateway-server
```

前端开发服务正常运行时刷新页面即可；生产部署使用本次打包的web构建。节点与协调器固件不因这项统计改动而需要重新烧录。
