# 新节点宣告不再误报静默重连

原来的设备宣告处理只检查 MAC 是否已经入库。新节点首次宣告创建内部记录，随后入网结束时再次宣告，就会错误地打印“静默重连”。

现在只在宣告到达之前，该设备已经有应用入网确认，且此前为离线状态或网络短地址发生变化时，打印一次“静默重连 / 已确认设备重新宣告”。未确认的新节点、多次相同地址的在线宣告、删除后重新添加的新记录均不打印。该日志仍只说明已登记节点再次宣告，不证明节点执行过协议栈重置，也不能区分已有 MAC 的设备在无线层使用了哪种入网方式。

地址映射、在线状态更新、入网确认、前端显示条件和设备发现逻辑不变。新节点正式可见时继续打印“节点入网确认”。

验证：`tests/run-announcement-log-tests.ps1` 提取实际设备宣告处理函数，连接真实数据库，覆盖首次/重复宣告、首次确认后重复宣告、离线后宣告、地址变化、删除重加及短报文；原入网显示回归与完整 Linux 后端编译通过。

修改前备份：`out/announcement-log-before-20261103/`。本次只更新后端，虚拟机重新 `make CC=gcc` 并启动即可，无需烧录节点或协调器。没有修改节点的上传失败判定或恢复策略。
