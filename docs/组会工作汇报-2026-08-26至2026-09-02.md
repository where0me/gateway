# Zigbee 工业网关阶段工作汇报

**汇报周期：2026年8月26日（上周三）—2026年9月2日**  
**涉及工程：Linux 网关后端、React 前端、CC1352R1 协调器、STM32WB55 终端节点**

## 一、本周工作概述

本周围绕工业状态监测网关完成了传感器采集、在线监测、振动数据可靠传输、数据库存储、前端展示以及 Zigbee 信道管理等功能。系统目前可以管理终端节点入网，采集温度、磁场、数字麦克风、模拟麦克风和三轴振动数据，并将同一轮采集结果按批次关联保存和展示。

本周工作重点是解决两个问题：一是让 1 秒三轴振动原始数据在终端内存有限、Zigbee 带宽较低的情况下能够完整保存并可靠上传；二是增加 Zigbee 自动/手动信道策略和已有节点网络迁移能力。

## 二、完成的主要功能

### 1. 完善两路麦克风采集与展示链路

- 接入数字麦克风和模拟麦克风采集结果，分别使用独立命令上报声级数据。
- 网关能够解析两路声级数据，保存设备最新值和历史记录。
- 前端分别展示数字麦克风声级和模拟麦克风声级，不再与温度混排。
- 增加两路麦克风最近 30 分钟趋势图，并按真实时间推进显示窗口。
- 模拟麦克风当前仍采用临时校准参考，前端已标注为估算值、待校准。
- 根据实际时钟配置，将采样率固定为：数字麦克风 46875 Hz、模拟麦克风 256000 Hz；采集窗口支持 0.5、1 和 1.5 秒。

### 2. 增加网关时间同步

- 前端启动时将浏览器时间同步给 Linux 网关，解决开发板没有可靠 RTC 时数据库时间错误的问题。
- 网关对传入时间进行合理范围校验，避免错误时间污染历史数据。
- 温度、声级、磁场和采集批次均能记录网关入库时间。
- 当前时间戳表示网关收到并写入数据库的时间，还不是终端侧的高精度采样起始时间。

### 3. 完善在线监测和采样策略

- 支持单节点和全部节点开启、关闭在线监测。
- 支持单节点和全部在线节点立即采集。
- 自动采集定时器放在终端节点，通过 RTC Timer Server 运行，不依赖前端持续在线。
- 开发阶段增加 1 分钟自动采集选项；正式应用仍建议使用 30 分钟及以上周期。
- 网关将采样策略保存在 SQLite 数据库中，节点重新连接后重新下发配置和在线监测状态。
- 固定三类传感器采样率，只允许前端修改采集窗口：振动、数字麦克风和模拟麦克风均支持 0.5、1、1.5 秒。
- 终端收到配置后会通过串口打印全部生效参数，便于确认实际配置。

### 4. 建立统一采集批次

- 每轮采集生成一个 32 位批次 ID。
- 同一轮温度、磁场、两路麦克风、振动特征和振动原始数据均携带相同批次 ID。
- 网关按 `(MAC, batch_id)` 关联数据，避免前端把不同采集轮次的数据混在一起显示。
- 前端在“本轮采集结果”位置显示采集批次和最近采样时间。
- 前端显示较短的批次序号，完整 32 位批次 ID 仍保留在内部用于唯一关联。

### 5. 完成振动采集、特征计算和外部 Flash 保存

- 终端使用 IIS3DWB 以固定 26667 Hz 采样率采集三轴振动。
- 振动采集窗口支持 0.5、1、1.5 秒，对应约 13334、26667、40001 个三轴点。
- 基于完整采样窗口计算 X/Y/Z 三轴 RMS、峰值、峰峰值、峭度和主频估计。
- 将完整原始振动数据先写入外部 QSPI NOR Flash，避免占用约 160 KB 的整批 MCU RAM。
- QSPI Flash 使用多槽结构保存待上传批次；未收到网关最终确认的数据不会被新采集覆盖。
- 支持终端复位后扫描 Flash，继续处理尚未确认的批次。
- 当前主频为去均值后的正向过零估计，不是 FFT 频谱主峰。

### 6. 设计并实现振动数据 V2 可靠传输协议

旧方案逐包等待确认，发送 26667 个三轴点耗时较长。本周完成新的分块压缩和窗口补传方案：

- 每 512 个三轴点组成一个独立压缩窗口。
- 使用“差分 + ZigZag + 自适应 Rice 编码”进行无损压缩，不使用哈希表。
- 如果某个窗口压缩后不比原始数据小，自动退回 RAW 原始格式，保证数据不会膨胀。
- 每个数据分片最多携带 72 字节压缩数据，窗口内连续发送，不逐包等待应用层确认。
- 网关按窗口统计缺失分片，通过 64 位缺包位图要求终端只补发丢失部分。
- 每个窗口和整批数据均进行 CRC32 校验，确保解压后的三轴数据与采集原始值一致。
- SQLite 成功提交完整批次后，网关才发送最终确认，终端随后才能释放对应 Flash 槽。
- 保留旧版振动协议解析，避免新旧命令混淆。

真实已有样本的软件测试中，26667 个 XYZ 点由 160002 字节压缩为 73188 字节，压缩后约为原始数据的 45.7%，解压结果逐字节一致。

### 7. 完善振动数据库和前端功能

- 数据库增加振动批次表，保存 MAC、批次、采样率、点数、特征、完整原始数据和时间戳。
- 同一设备同一批次支持幂等处理，避免重传造成重复入库。
- 检测批次参数或 CRC 冲突，防止错误数据覆盖已有数据。
- 前端显示 X、Y、Z 三轴振动特征，每个轴单独一行，解决原先特征错位问题。
- 前端保留原始波形展示和下载入口。
- 上传过程中显示已校验窗口数和总窗口数，完成后只显示“上传完成”，不表述为已上传远程服务器。
- 节点卡片展开时主动刷新详情；周期采集或手动采集完成后自动刷新当前展开卡片。

### 8. 完善节点入网、重连和彻底移除

- 支持扫描发现、设备信息查询、白名单入库和未授权节点清理。
- 已授权节点重新入网时，以 64 位 MAC 识别设备并更新新的网络短地址。
- 新入库节点默认关闭在线监测，修复删除后重新加入时前端短暂显示为开启的问题。
- “彻底移除”会删除数据库中与设备有关的设备影子、温度、磁场、声级、同批采集值和振动批次。
- 协调器向终端发送不允许自动重连的离网操作；终端被移除后本次运行不再自动入网，按 RESET 或重新上电后才能再次尝试入网。

### 9. 增加 Zigbee 信道策略和网络迁移

- 系统设置页面删除未使用的“网关连接”模块。
- 增加自动信道策略和手动信道 11～26 下拉选项。
- 将 11、15、20、25 标为首选信道，其余合法信道标为次选信道。
- 自动策略用于下次建网选择信道，不主动扰动当前网络。
- 空网络可以直接切换信道；已有节点时，协调器通过标准 `Mgmt_NWK_Update` 执行全网迁移。
- 启用协调器 Z-Stack 的网络更新功能，解决原先返回 `0x12`、无法执行迁移的问题。
- 节点正在采集或上传时拒绝迁移，避免切换过程破坏当前采集批次。
- 正常信道迁移不会改变节点短地址；数据库仍以 MAC 作为稳定设备标识。

### 10. 增加信道切换等待和最终结果确认

- 切换期间前端显示全屏等待窗口并持续转圈，禁止用户进行其他鼠标、触摸和键盘操作。
- 协调器 `0x96` 应答只表示迁移请求是否被受理，不再直接当成切换成功。
- 网关每秒查询一次协调器网络信息，以 `0x8A` 返回的实际信道作为最终判断依据。
- 实际信道等于目标信道才显示成功；协调器拒绝或等待超时则显示失败。
- 成功和失败窗口均显示协调器当前实际信道。
- 操作结束后，前端下拉策略和数据库配置均回填为协调器当前实际信道，避免“策略为15、实际仍为11”的不一致。

## 四、数据库与接口完善

本周完善的主要数据表包括：

| 数据表 | 用途 |
| --- | --- |
| `devices` | 设备白名单、短地址、在线状态、监测状态和最新值 |
| `monitor_config` | 自动采集周期、轮询周期、采样率和采集窗口 |
| `zigbee_config` | 自动/手动信道策略和目标信道 |
| `temperature_data` | 温度历史 |
| `magnetic_data` | 三轴磁场历史 |
| `sound_data` | 数字/模拟麦克风声级历史 |
| `collection_values` | 同一批次的温度、磁场和两路声级 |
| `vibration_batches` | 振动特征、完整原始波形、采样参数和批次时间 |

彻底移除设备时，以上与该 MAC 相关的数据会一起删除。

## 七、组会口头汇报简版

上周三到现在，我主要完成了三部分工作。第一，打通了温度、磁场、数字麦克风、模拟麦克风和振动数据的完整采集链路，并用统一批次保证前端显示的是同一轮数据。第二，针对一秒振动原始数据量大、终端 RAM 不够和 Zigbee 传输慢的问题，增加了外部 Flash 多槽保存、分块无损压缩、窗口连续发送、缺包位图补传和整批 CRC 校验，网关能够解压后保存完整波形。第三，增加了 Zigbee 自动和手动信道策略，已有节点时可以进行全网信道迁移，并且前端会锁定等待，以协调器返回的实际信道判断成功或失败。目前软件编译和协议测试已经通过，下一步重点是在真实硬件网络中测试振动上传效率、断电恢复和信道迁移稳定性。
