# 9D上传失败后的重连探测恢复

本次仅修改实际双模节点工程 `C:/Users/Administrator/STM32-Projects-1.91/STM32WB55RGV6-BLE-Zigbee` 的恢复流程。协调器、前后端、排队策略及Flash槽位策略没有改动。

## 复现与修复

9D批次2850209704完成25/27窗口后出现信道接入失败和APS未确认。节点在522.252秒停止上传并验证父节点，544.386秒提交第三次重连探测，但547.391秒外层恢复定时器沿用旧期限触发。旧代码作废发送回调，却保留 `rejoin_probe_pending` 和 `rtc_join_active`；后续启动恢复被这些状态阻挡，循环打印15秒重试而无新尝试。

修复内容：

- 每次成功排入新的父节点APS/ZDO探测，重新给予完整10秒确认预算；提交失败不延长期限。
- 当前APS探测回调完成后，为正常5秒重试保留15秒外层预算。
- 外层超时先停止旧重试定时器，作废旧回调，再清除本轮父节点、重连候选、RTC恢复和ZDO等待状态，启动新一轮安全恢复。
- 同步 `ZbStartup` / `ZbStartupRejoin` 尚未返回时，嵌套任务不清理或并发重启协议栈操作。
- 迟到ZDO回调先检查代次与当前等待状态，不能清掉新探测的在途标记。
- 日志明确区分“探测超时，结束旧轮次”与“重新启动安全恢复”，不再仅打印15秒后重试。

运行时恢复不擦除网络NVM、网络密钥和外部Flash批次。连接真实验证成功并完成设备宣告后，重新申请最早未上传批次的许可。普通无线失败仍可能发生，本次处理的是失败后无法继续恢复的问题。
