# 节点协议栈自动低功耗及最大发射功率

修改范围：纯 Zigbee 节点 `STM32_WPAN/App/app_zigbee.c`。前端、后端、协调器不变。

- 已授权节点采集上传后的 CPU1 STOP2 路径保留；CPU2 无线固件自行选择低功耗模式。
- 未入网节点结束 30 秒尝试并完成在途操作收尾后，仍等待五分钟再尝试；不再调用 ZbStatePause/ZbStateResume。
- 五分钟等待状态仅表示应用等待，不能作为整个无线子系统已停止的证明。
- 保留 SED RxOnWhenIdle=false 和原有快速 Poll、恢复握手、持久化及删除清理流程。
- 使用 ZbNwkIfSetTxPower(zb, "wpan0", 6)，并通过 GetTxPower 读回核实。初始化、栈重置、入网/重入及恢复后的公告任务中核实设置。STOP2 不主动降低功率。
- 接收功率不存在同类 +6 dBm 设置；不改无线寄存器、不强制持续接收。CPU1 未进入 STOP2 也不意味着射频必须常开。
- 日志 `verified=1` 只证明软件设置及读回一致，不是天线端功率测量。

官方依据：AN5289 §4.6（CPU2 无线固件管理自身低功耗）；AN5732 §3–5（睡眠终端与 Poll）；AN5500 §8.3.8–9（发射功率设置和读取）。

构建标识：`stack-low-power-20261003-a`。Debug/Release 编译验证通过；未烧录硬件。需要板上检查 +6 dBm 读回、已授权节点周期采集，以及未入网节点五分钟重试。
