# 上传消息去重与阶段日志（2026-10-19）

## 范围

修改融合节点 `STM32WB55RGV6-BLE-Zigbee/STM32_WPAN/App/app_zigbee.c` 和网关后端；不修改 TI 协调器、蓝牙实现、前端、串口波特率、无线帧格式、排队算法或分块确认机制。

## 行为

- 节点采集完成、准备申请许可时不再上报 UPLOADING；取得 BATCH/OK 后，每个上传尝试仅排入一次 UPLOADING 状态。状态队列暂满会稍后再试，不因此重新排入整份测量数据。
- 上传申请接受时打印“上传许可：批次申请已接受，等待节点发送数据”，不再误报为波形已到达。
- 首个有效波形分片到达才打印“开始接收原始波形”。首块计时从第一个实际收到的有效分片开始，即使不是序号 0。最后一个缺失分片到达时先打印收齐，再解码、CRC 校验并打印“已校验 1/N”。收齐日志明确标记“校验前”，不能当作校验成功。
- 温度、磁场及两种声级以数据库里的 MAC + 批次 + 数据字段判重。完全相同的重报不重复打印、发布数据事件或插入历史记录，也不改变该批次时间戳；仍刷新设备通信活动。新批次即使数值一样也正常保存，同批数值修正也正常保存。
- 标量的批次记录、最新值和历史记录在同一 SQLite 保存点内提交；失败回滚，不会把失败数据误标为已经处理而拒绝重试。使用数据库连接互斥锁保护组合操作。
- 振动特征摘要按数据库里同一 MAC + 批次的采样率、点数及 15 个特征值判断是否已保存。相同摘要不重复发布、打印或更新数据库时间戳，但仍回复 FEATURES/OK；失败仍返回 STORE_FAILED。重启后依旧可识别已保存摘要。
- 业务状态按最近一次同批状态过滤重复。COMPLETE 后的旧状态不再回退；ERROR -> UPLOADING 作为正常重试保留。空闲心跳的 LQI/RSSI、电源等更新不受影响。
- 相同配置查询及实际下发内容在 10 秒内合并日志，但每次查询仍正常回复。内容（包括监测开关、迁移标志）改变立即打印；A -> B -> A 也视为真实修改。
- 同批排队请求在 10 秒内合并提示，但每次仍返回 WAIT 和当前估计。后续再次等待显示“排队复查”，不新增队列位置。等待估计仍会动态变化，并非固定上传时刻。

状态／配置／排队提示缓存有界、仅在当前后端进程内有效，满后淘汰最旧项；重启后这些提示可能重新出现。标量及特征摘要去重依赖数据库，可跨后端重启。不同节点、不同发送通道的消息仍按实际到达顺序处理，不人为重排或延迟数据来制造固定日志顺序。
